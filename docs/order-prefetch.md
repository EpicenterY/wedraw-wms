# 빈 선행 공급과 완료 빈 회수 · v1.12.0

## 이번 원인과 변경

- 빈을 꺼내기 전 입구를 예약하면 이동·승강 중에도 포트 회전과 완료 빈 회수가 막혔습니다. 선행 공급을 켜면 먼저 빈을 실제로 들어 포트 근처로 옮기고, 인계 단계에서 입구를 예약합니다. 1대 운용이나 안전한 대기 공간이 없는 레이아웃은 가능한 직접 공급으로 진행합니다.
- 선행 운반 로봇은 예정 포트까지의 직교 거리가 가까운 위치부터 검사해 대기합니다. 두 칸 차체가 포트 입구·회수 접근 영역을 덮지 않아야 하며, 다른 로봇의 접근성과 저장 영역 접근을 유지해야 합니다. 안전한 위치가 없으면 무리하게 들어 올리지 않습니다. 새 직접 공급은 해당 포트의 기존 선행 운반을 추월하지 않습니다.
- 피킹이 곧 끝나는데 가까운 빈 로봇을 다른 먼 작업에 보내면 회수가 늦어졌습니다. 남은 피킹이 10초 이내이거나 회수할 빈이 있을 때, 접근 가능한 2.5m 이내의 적합한 로봇 한 대를 우선 회수에 남깁니다. 회수 가능한 완료 빈은 새 공급 예약보다 먼저 배정합니다. 회전·셔터·승강의 기존 안전 잠금은 그대로 유지합니다.
- 선행 리프팅은 포트별 최대 1대, 전체 가용 로봇 수보다 최소 1대 적게 허용합니다. 모든 남은 로봇이 순간적으로 작업 중이라는 이유로 준비를 막던 조건을 제거하고, 대신 가까운 회수 로봇 확보와 포트별 대기를 함께 조율합니다. 남은 피킹·다음 수량·준비 시간을 보고 지나치게 이른 리프팅은 보류합니다. 준비량을 늘린 실험에서는 회수와 경로 혼잡이 증가해 적용하지 않았습니다.
- 일반 고객 주문·품목의 목록 순서 페널티를 제거했습니다. 준비·이동·포트 잔여 시간을 기준으로 선택하며 명시적 긴급 주문의 우선권은 유지합니다. 재배치·회수 시 다음 주문 빈을 덮지 않는 가까운 위치를 우선합니다.
- 긴급 승격된 빈이 로봇에 실려 있어도 Rust가 예정 포트의 선행 회수를 계산합니다. 협업을 끄면 자기 포트 빈을 회수해야 하는 로봇이 다른 빈을 선행 리프팅하여 자기 회수를 막지 못하도록 합니다.

설정의 **빈 선행 공급**에서 켜고 끕니다. 저장 키와 기존 사용자의 선택은 유지됩니다. 피킹 시간은 기존처럼 0.5~60초/개이며 수량에 따라 합산됩니다.

## 원인과 변경

- v1.10.0은 그리드에서 빈을 들기 전부터 포트 입구를 예약했습니다. 빈이 도착한 뒤에도 후면 인계 예약이 앞쪽 작업대의 피킹 **시작**까지 막았습니다. v1.11.0은 이미 작업 위치에 정렬된 빈의 피킹과 후면 인계를 병렬 허용합니다. 회전 중 피킹 금지, 입구 예약 중 회전 금지, 셔터 개방·안착 조건은 그대로 검증합니다.
- 즉시 포트로 보낼 수 있으면 직접 공급합니다. 그렇지 않으면 포트 예상 잔여 작업과 다음 요청의 수량·피킹 시간을 보고 먼저 리프팅합니다. 같은 포트에 선행 리프팅은 최대 1개이며 전체 한도는 가용 로봇 수의 약 1/3입니다. 시작 후에도 최소 1대의 미배정 로봇을 남겨 회수를 방해하지 않습니다. 준비 시간대가 맞지 않으면 0개로 줄입니다. 깊은 빈의 디깅 준비 한도는 포트 정원과 준비 시간에 따라 조절합니다.
- 리프팅한 빈은 실제 로봇에 귀속된 채 안전한 위치에서 기다립니다. 빈 소유권, 작업 잠금, 시간 경로 예약을 유지하고, 인계가 가능해지면 같은 로봇이 이어서 배송합니다. 옵션을 끄거나 우선 주문이 추가돼도 이미 들어 올린 빈을 버리거나 중복 배정하지 않습니다. 1대 로봇은 직접 공급만 사용합니다.
- 고객 목록 순서를 유지하되 준비된 빈의 피킹을 불필요하게 늦추던 강한 순서 페널티를 낮췄습니다. 포트에서는 이미 작업 위치에 있는 빈과 도착한 빈을 처리합니다. 긴급 주문 우선권과 필요한 선행 회수는 유지합니다.

## 지표를 구분해야 하는 이유

기존 **포트 빈 대기**는 피킹/대기 빈이 없는 시간만 셌습니다. 도착한 빈이 회전·인계 예약 때문에 피킹하지 못하는 시간은 빠져 있었습니다. 따라서 이제 이름을 **공급 빈 없음**으로 명확하게 표시하고, **피킹 중단**을 별도 제공합니다. 후자는 미피킹 수요가 남아 있는 동안 실제로 피킹하지 않는 시간이며 회전·안착·인계·공급 부족을 포함합니다. 둘 다 포트별 합계라서 전체 경과 시간보다 클 수 있습니다. 기존 값을 삭제하거나 재정의하지 않았습니다.

## 화면 끊김 개선

- 한 프레임에서 큰 시간 덩어리를 처리하던 방식을 최대 0.05 모의 초의 작은 단계와 6ms 계산 예산으로 분산했습니다. 일시정지·배속 변경 때 밀린 시간을 털어 갑작스러운 점프를 방지합니다. 상태 전이를 건너뛰지 않으며 CPU가 부족하면 요청 배속보다 느리게 진행할 수 있습니다.
- 바쁜 로봇의 불필요한 후보 경로 탐색을 제거했습니다. 배정 단계 안에서 차단 셀·도달 가능 영역·주차 안전성 검증을 재사용하며 배정 후 캐시를 폐기합니다.
- 바퀴 승강량이 그대로면 형상을 재사용하고, 동적 정점 메모리와 GPU 버퍼를 재사용해 프레임마다 할당하는 양을 줄였습니다.
- 이 예산은 단일 배정 계산을 중간에 끊지는 못합니다. 매우 큰 그리드나 많은 로봇에서 모든 프레임의 시간을 보장하는 방식은 아니며, 60FPS 달성을 주장하지 않습니다.
