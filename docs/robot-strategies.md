# 로봇 운용 전략 · v1.6.0

v1.10.0의 별도 **주문 순서 선행 준비** 옵션과 피킹 시간은 [추가 검증](order-prefetch.md)을 참고하세요. 아래 수치는 v1.6.0 당시의 비교입니다. 현재 기본 배정으로 돌아가려면 선행 준비도 꺼야 합니다.

## 조작과 호환성

더보기 → 로봇 운용 전략의 세 스위치는 독립적으로 저장됩니다. 웹 UI의 최초 기본값은 모두 켜짐입니다. 엔진 API에서 strategies를 생략하면 기존 동작을 유지합니다. 모두 끄면 기본 배정으로 돌아가며 이미 시작한 작업, 시간 예약, 빈 소유권, 포트 슬롯은 끝까지 유지합니다. 일시정지 중에도 옵션을 바꿀 수 있습니다. 새로고침은 기존 앱 규칙대로 저장된 주문 정의를 대기 상태로 복원합니다.

## 세 전략

- **완료시간 기반 배정**: 실행 가능한 작업·로봇 후보의 이동/승강/디깅 시간, 포트 대기 예상, 다음 작업까지의 접근 거리, 주문 대기 시간을 점수화합니다. 후보별 다음 디깅은 깊이당 8초의 추정값이며 전역 최적해를 보장하지 않습니다. 작업당 최대 3개의 실행 가능한 로봇 후보를 평가하고, 일반 미시작 작업은 후보 수 24개를 채우면 더 추가하지 않습니다. 진행 중 주문과 긴급 주문은 이 후보 제한에서 제외합니다.
- **포트 흐름 조율**: 포트의 남은 피킹·회전·예약된 빈을 고려해 배달 포트를 선택하고, 빈 공급이 없는 포트의 배달과 슬롯을 비워야 하는 회수를 우선합니다. 동시 준비 주문은 운영 가능한 포트의 총 슬롯 수를 기준으로 제한하되 긴급 주문은 예외입니다. 로봇 역할은 작업별로 바뀌며 고정 전담 대수를 만들지 않습니다.
- **시간대별 경로 예약**: 두 칸 로봇의 전체 몸체와 가감속을 포함한 이동 구간, 정지/승강 작업의 점유 시간을 예약합니다. 동일 셀을 시간차로 통과할 수 있고 필요하면 출발 지점에서 최대 12초 기다립니다. 경로 중간 재계획이나 속도 변경은 하지 않습니다. 끝 위치는 다음 작업이 시작할 때까지 점유합니다. 기존 작업과 충돌하면 다른 후보를 택하거나 다음 배정 주기를 기다립니다.

웹 어댑터가 경로와 동작 후보를 만들고 Rust/Wasm이 점수 선택, 시간 충돌 검사 및 배정 승인을 수행합니다. 빈/스택 자원은 승강 종료까지 별도 독점 잠금으로 보호합니다. 시간 예약은 제안할 때와 실제 배정할 때 다시 검사합니다. 일반 경로 잠금을 사용하는 기존 작업과 새 시간 예약 작업의 혼합도 지원합니다.

실제 물류 장비 제어를 위한 안전 인증·통신·실시간 보장은 포함하지 않는 시뮬레이터입니다.
