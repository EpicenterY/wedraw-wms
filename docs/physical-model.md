# wedraw WMS 물리 모델과 공개 사양의 적용 범위

이 문서는 화면에 사용하는 공개 치수, 앱이 재구성한 설치·동작 모델, 추가 현장 자료가 필요한 부분을 구분한다. 공개 제품 사양을 적용하고 실제 빈 소유권·재고·이동 경로·간섭을 검사하지만, 특정 AutoStore 설치의 승인 도면이나 OEM 제어기를 재현한 모델은 아니다.

빈의 8색 팔레트와 명암 대비는 화면에서 개별 빈을 구분하기 위한 시각화다. 색상은 빈 ID에 고정되므로 디깅·운반·포트 피킹·복귀 중에도 유지되며, SKU 분류나 실제 제조사의 빈 색상을 뜻하지 않는다. 빈 외곽 치수와 적층 피치는 이 표현 때문에 변경하지 않는다.

705 × 480 mm는 SDG를 선택한 값이다. DDG의 짧은 방향 간격인 505 mm와 혼용하지 않는다. 6 m를 입력해도 220 mm 빈을 27층으로 만들지 않으며, 최대 26층·명목 적층 5.72 m로 제한한다. 330·425 mm의 최대 명목 적층 높이는 각각 5.94 m와 5.95 m다.

외곽 높이와 적층 피치는 같은 개념으로 단정할 수 없다. 현재 엔진은 공개된 명목 높이를 적층 피치로 사용한다. 바닥 기준면 15 mm, 림 결합 공차, 실제 적층 시 맞물림 형상은 현장 CAD로 보정해야 한다. 화면의 `actualHeightM`는 이 명목 적층 높이이며, 로봇·건물 천장·정비 여유까지 포함한 설치 전체 높이가 아니다. Grid FAQ는 로봇 상부 운행 여유와 별도로 정비 공간을 안내한다.

## 2. 포트의 설치 영역과 실제 재고 공간

### 두 후방 인계점

버퍼 포트를 지정한 셀은 첫 번째 후방 인계점이다. 같은 외곽 변에서 두 셀 떨어진 두 번째 인계점과 그 사이 상부 레일을 사용한다. 로봇은 이 두 격자 위치 중 비어 있는 트레이 위로 직접 빈을 내려놓는다. 기존의 한 샤프트에서 세 트레이까지 가로질러 이동하던 가상 셔틀은 사용하지 않는다.

두 인계점과 전방 작업점을 120° 간격의 회전 트레이로 연결한다. 이 배치는 공개 설명을 따르는 **기구 재구성**이며, 선택한 인계점 간격이나 회전 반경이 OEM 실측값이라는 의미는 아니다.

| 앱의 기구 설정 | 값 / 계산 |
| --- | --- |
| 선택한 작업 높이 | 빈 상단 접촉면 0.960 m. 공개 작업 높이 범위 안에서 채택한 설정값 |
| 빈 바닥 높이 | 0.960 m − 해당 빈 외곽 높이 |
| X 방향 외곽 포트의 후방 인계점 간격 | 2 × 0.480 = 0.960 m |
| Z 방향 외곽 포트의 후방 인계점 간격 | 2 × 0.705 = 1.410 m |
| 회전 반경 | 인계점 간격 ÷ √3: 약 0.5543 / 0.8141 m |
| 회전 중심 | 두 인계점의 중점에서 외곽 방향으로 반경의 절반만큼 이동 |
| 전방 작업점 | 회전 중심에서 외곽 방향으로 반경만큼 이동 |
| 빈 방향 | 그리드의 긴 축·짧은 축 방향을 유지 |

반경을 외장 안에 보이도록 임의로 줄이면 빈끼리 겹친다. 고정 방향의 649 × 449 mm 빈 세 개를 120° 간격으로 회전시키는 이 모델에서는 빈 대각선 약 789 mm보다 트레이 중심 간격이 커야 모든 각도에서 간섭을 피할 수 있다. 채택한 960 / 1,410 mm 간격은 이 조건을 충족한다.

### 전면 가구와 후면 기구 영역의 구분

공개 가구 폭·깊이를 전체 회전 궤적 또는 설치 면적과 같다고 가정하지 않는다. 전면 가구는 공개 SDG 치수를 사용하고, 뒤쪽 회전 암·두 인계 샤프트·빈의 연속 이동 공간은 별도의 재구성 영역으로 잡는다. 특히 Z 방향 외곽의 큰 회전 반경에서는 후면 영역이 공개 전면 가구 폭보다 넓어진다. 실제 설치 치수 확정에는 제조사의 설치 도면이 필요하다.

엔진과 렌더러는 `port-footprint.js`의 동일한 외장·인계 타워 평면을 사용한다. 회전 중심 궤적과 실제 649×449 mm 빈의 합집합을 보수적인 둥근 사각 외곽으로 계산하며, 벽 두께와 빈 사이 간격을 포함한다. 예약 셀 전체나 회전 궤적의 큰 사각 바운딩 박스를 외장으로 채우지 않는다. 후면 외장은 작업 높이까지만 두고, 그리드 높이까지 올라가는 부분은 실제 두 인계 샤프트에 한정한다. 벽 두께는 평면 경계 안쪽으로 배치한다.

엔진은 이 설치 평면과 셀 영역이 겹치는 그리드 열을 `isEquipment`로 예약한다. 예약된 열에는 저장 빈을 배정하지 않으며, 용량 계산에서도 제외한다. 상부 격자와 로봇 주행은 유지한다. 실제 설비가 일부 높이만 사용하는 경우에도 해당 열 전체를 저장에서 제외하는 보수적 모델이다.

`footprintReservedKeys`, `layout.equipmentCells`, `installationBounds`로 같은 설치 영역을 화면과 공유한다. 가구·후면 하우징의 접합부 내부에는 빈 이동을 가로막는 벽이 없어야 하며, 예약 영역을 통과하는 기존 저장열 지지틀을 그대로 그리면 안 된다. 이 공간 처리와 별개로 실제 구조 보강·하중 검토는 수행하지 않는다.

작업자 전면이 외부로 연결되지 않는 배치, 두 후방 인계점이 없는 배치, 포트끼리 설치 영역이 겹치는 배치는 운영 불가로 표시한다. 설정 좌표를 다른 곳으로 몰래 옮기지 않는다.

## 3. 접근창과 피킹 조건

외장 화면에서는 모든 실제 빈을 외장 안에 그리며, 벽이 뒤쪽 빈을 가린다. 상단 커버만 95% 불투명도로 그려 내부가 희미하게 비친다. 열린 작업창은 도착 중이거나 정지한 빈을 보여주며, 접근 가능한 피킹 빈은 정지·안착이 끝난 한 개로 별도 관리한다. 점검 보기에서는 내부 기구와 실제 빈들을 볼 수 있다.

회전은 피킹과 그리퍼 인계가 끝나면 시작하며, 열린 창은 회전 시작과 동시에 0.8초 동안 닫힌다. 첫 0.8초의 닫힘과 마지막 20% 각도의 열림 외에는 회전 중 창이 닫혀 있다. 3빈 포트는 실제 회전각의 80%부터 도착할 대기 빈을 보여주며 창을 연다(`approaching`). 회수 전용 회전에서는 열지 않는다. 회전 정지 후 최소 0.35초 안착과 완전 열림을 모두 충족해야 피킹을 허용한다. 회전·열림·닫힘 중에는 `accessibleBinId`를 제공하지 않는다. 일반 포트는 기존처럼 정지·안착 후 창을 연다.

이는 앱의 **접근 차폐·피킹 조건 모델**이다. 공식 [Workstations FAQ](https://www.autostoresystem.com/faq/workstations)는 CarouselPort의 감응식 safety cover와 다른 포트들의 자동 safety hatch를 구분한다. 이 앱의 자동 열림·닫힘을 실제 CarouselPort 4.0의 안전 제어 방식이나 안전 인증으로 설명하지 않는다.

화면 계약:

```js
port.aperture = {
  state: 'closed' | 'opening' | 'open' | 'closing',
  openness: 0 // 0..1
};
port.presentation = {
  state: 'hidden' | 'approaching' | 'settling' | 'opening' | 'presented' | 'closing',
  binId: null,
  pickAllowed: false
};
port.accessibleBinId; // 완전히 열린 창에서 실제 피킹할 수 있는 빈만 반환
```

## 4. 1층 설계와 운영 가능성

1층부터의 그리드 편집·보관 수용량·재고 열람은 유지한다. 포트 작업대를 낮은 그리드에 맞춰 바닥으로 줄이지 않는다. 공개 최소 층수보다 낮으면 카탈로그와 배정 상태는 유지하되 다음과 같이 처리한다.

- `reachable`: 두 칸 로봇이 포트 좌표까지 도달할 수 있는지 나타내는 기하학적 상태.
- `operational`: 설치 조건을 충족하는 포트로 출고할 수 있는지 나타내는 별도 상태.
- `operationalSkuCount`: 실제로 운영 가능한 포트 경로가 있는 배정 SKU 수.
- `enqueueSku`: 운영 불가능한 품목 요청을 이유와 함께 보류.
- `start`: 운영 가능한 포트가 없으면 실행 거절.

그리드·높이·포트 설정 변경 시 시뮬레이션을 초기화하는 정책은 유지한다.

## 5. 시간·동작 가정과 검증 범위

아래 시간은 현장 측정값이 아니다. 공개 최소 교환 시간 2.5초나 최대 처리량을 앱의 처리량으로 대입하지 않는다.

| 동작 | 현재 모델 설정 |
| --- | --- |
| 접근창 열기 / 닫기 | 각 0.8초 |
| 안착 확인 | 0.35초 |
| 120° 트레이 인덱싱 | 3.2초, 시작·종료 속도 0인 quintic 곡선 |
| 작업자 피킹 | 요청당 14초 + 수량 × 0.8초 |
| 로봇 수평 이동 | 모델 속도 상한 1.8 m/s, 거리 기반 가감속 |
| 로봇 승강 | 모델 속도 상한 1.15 m/s, 거리 기반 가감속 |
| 인양 체결 / 해제 | 각 0.4초 |

빈 소유권은 그리드·로봇·포트 중 항상 하나에만 속한다. 체결·해제 시점의 위치 연속성, 재고 수량 보존, 포트 총 3자리 제한, 한 번에 한 빈 피킹, 두 칸 로봇의 상부 레일 주행, 빈끼리와 인접 저장 빈의 겹침을 검사한다. 후방 두 인계점은 모델에서 보수적으로 직렬 예약한다.

협업 디깅은 같은 열에서 상부 빈을 한 개씩 인양하되, 앞선 로봇이 해당 열을 완전히 벗어나면 다음 로봇의 인출과 앞선 빈의 운반·적재를 병행한다. 빈을 체결해 스택에서 제거한 시점만으로 다음 로봇의 접근을 허용하지 않는다. 현재 연속 위치에서 차지하는 두 칸과 이동 중 지나치는 영역, 남은 경로와 승강 작업 위치를 예약으로 보호한다. 지나간 영역이라도 이후 복귀 경로에서 다시 사용할 경우 예약을 유지한다. 한 요청의 복수 작업을 함께 추적하여, 먼저 끝난 재배치가 다른 로봇의 작업 상태나 목표 빈의 소유권을 해제하지 않도록 한다. 협업을 끄면 한 로봇이 해당 요청을 순차 처리한다.

이송 완료 후 로봇은 기본 주차점으로 자동 복귀하지 않는다. 적재 후 그리퍼를 완전히 올린 상태에서 다음 임무를 현재 위치로부터 배정한다. 현재 위치가 후속 인출이나 공용 인계점 접근을 막으면 가까운 안전 위치까지 이동한다. 전체 로봇의 예상 종료 위치에서도 기존 저장 열과 운영 포트 접근성이 유지되는지 확인하며, 순차 처리 모드는 해당 요청의 고정 담당 로봇 접근성도 유지한다. 설정 상한은 30대이고, 작은 그리드의 실제 배치 수는 2셀 경로와 주차 조건에 따라 제한된다.

실측 보정에 필요한 자료는 설치 CAD, 빈 적층 결합 피치와 공차, 실제 암 궤적과 독립 구동 순서, 인계 샤프트/하부 지지틀 치수, 로봇과 포트의 가감속·지연 로그, SKU 실물 형상·중량이다. 구조 강도, 벨트 장력, 마찰, 모터 토크, 안전 센서·PLC 로직, 작업자의 실제 동작 시간은 현재 계산하지 않는다.

## 6. 주문 빈도 기반 유휴 재배치

앱은 고객 주문 정의에서 각 주문에 포함된 빈을 한 번씩 세어 `setDemandWeights([{binId, orderCount}], {sampleSize})`로 전달한다. 아직 실행하지 않은 주문도 빈도 자료에 포함될 수 있지만, 자동 운영을 명시적으로 시작하기 전에는 로봇이 움직이지 않는다. 이는 관측된 주문 빈도에 대한 규칙 기반 배치이며 미래 수요를 예측하는 학습 모델은 아니다.

유휴 최적화를 켜면 대기·진행 출고 요청과 포트의 잔류 빈이 없을 때만 고빈도 빈을 선택한다. 위의 빈을 실제로 한 개씩 옮긴 뒤 대상 빈을 다른 저장열 맨 위에 적재한다. 현재 수요 가중치가 있는 다른 빈을 다시 덮지 않도록, 목적지는 수요 가중치가 0인 빈들로만 구성된 여유 열로 제한한다. 접근 가능한 목적지와 모든 이동의 용량을 먼저 계획한다. 이런 목적지가 없으면 배치를 억지로 바꾸지 않는다.

이동은 출고와 같은 로봇, 네 벨트 승강, 체결·해제, 두 칸 주행 경로·잠금, 빈 소유권을 사용한다. 실제 적재가 완료될 때만 `optimizationMoves`를 늘리며, 대상 고빈도 빈 자체가 다른 열 맨 위로 이동한 경우에만 완료 빈으로 기록한다. 새 출고 요청이 들어오면 그 요청을 우선 배정한다. 이미 들고 있는 빈은 현재 이동·적재·그리퍼 복귀와 필요한 통로 확보를 마친 다음 후속 최적화 작업을 취소한다.

수요 빈들이 이미 맨 위에 있거나 개선할 여유 열이 없으면 빈을 계속 섞지 않고 **운영 대기** 상태로 새 주문을 기다린다. 일시정지는 출고·포트·최적화를 함께 멈춘다. 자동 최적화는 엔진 API에서 명시적으로 켜는 기능이며, 비활성화한 일반 시뮬레이션은 요청 완료 후 기존처럼 종료된다.

기구 이해에 참고한 추가 1차 자료는 AutoStore의 [WO2024133111A1, System and method for weighing containers](https://patents.google.com/patent/WO2024133111A1/en), 특히 도면 5–7의 트레이·암·하부 링과 지지 휠 구성이다. 이 특허의 예시를 특정 판매 제품의 승인 도면으로 취급하지 않는다.


## 7. 일반 1빈 포트와 피킹 시각화 (v1.8.0)

일반 포트는 기존 1.10 × 0.82 m 작업대와 단일 승강 샤프트의 합집합 설치 영역을 유지하는 재구성 모델이다. 수직 인계점과 피킹 빈 위치는 같다. 전면에는 약 532 mm 높이의 롤업 작업창을 두고, 앞벽 상부·측벽·후벽은 승강 통로를 둘러싼다. 셔터는 전면 평면에서 수축하며 빈의 수직 통로를 가로지르지 않는다. 좁은 하부 샤프트 접합부의 라이너는 10 mm, 상부 작업구 테두리는 8 mm로 모델링해 실제 빈 외곽을 침범하지 않게 했다. 이 치수와 바코드 리더기 배치는 앱의 시각적 재구성이며 OEM 승인 CAD가 아니다.

피킹 물품은 130 × 85 × 90 mm의 일반 상자로 표시한다. 피킹 요청당 한 번 상승·제시·스캔·확인·반출하며 재고 단위 수와 1:1 대응하지 않는다. 스캐너는 물품을 바라보는 고정 형상이고 라벨·빛·녹색 확인 표시는 진행률 기반 시각화이다. 하드웨어 판독과 안전 인터록 인증은 구현하지 않는다. 테스트는 네 방향·세 빈 높이의 전체 승강 공간, 저장 셀 간섭, 전면 개구부와 스캐너 시야, 애니메이션 연속성과 소유권을 검증한다.

## v1.9 로봇 표시 동작

본체 지붕은 레일 위 640mm, 상판 두께는 38mm로 모델링하며 완전 복귀한 접촉면 높이는 602mm이다. 본체 번호와 리프트 심볼의 표면은 모두 642.5mm로 일치한다. 벨트 앵커는 635mm로 조정하여 완전 복귀 시에도 벨트가 역전되지 않는다. 방향별 비활성 바퀴의 18mm 승강은 시각화이며 주행 속도·충돌 예약·차체 방향을 변경하지 않는다. 이동 구간 시작·종료 시 두 쌍이 레일에 내려오고, 주행 중 비활성 축만 올라간다. 모든 값은 이 앱의 재구성 값이다.
