# wedraw WMS

[실행 중인 데모](https://wedraw-wms.vercel.app/) · [GitHub 소스](https://github.com/EpicenterY/wedraw-wms)

웹 화면과 Rust/WebAssembly 계산 코어로 구성한 물류창고 시뮬레이터입니다. 이 저장소는 배포된 **v1.12.0** 소스의 공유용 스냅샷이며, 원본 기준 커밋은 `102956e3f578e993c5680472ade66a41ad8a4ca7`입니다. 실제 장비와 연결하지 않습니다.

## 빠른 실행

Node.js 24 LTS와 Git이 있으면 포함된 WebAssembly 빌드로 바로 실행할 수 있습니다. npm 의존성 설치는 필요하지 않습니다.

```sh
git clone https://github.com/EpicenterY/wedraw-wms.git
cd wedraw-wms
npm run dev
```

브라우저에서 [http://127.0.0.1:4173](http://127.0.0.1:4173)을 여세요. HTML 파일을 직접 여는 대신 로컬 서버로 실행합니다. 설계와 옵션은 각 브라우저에 저장됩니다.

## Rust 수정·빌드·검증

Rust를 수정하려면 Rustup이 필요합니다. `rust-toolchain.toml`이 Rust 1.100.0과 `wasm32-unknown-unknown` 타깃을 지정합니다.

```sh
npm run build
npm test
```

빌드 결과는 `dist/wasm/`에 저장됩니다. 테스트는 실제 Rust/Wasm으로 재고·빈 소유권·포트 전이·긴급 주문·로봇 충돌과 화면 동작을 검증합니다. 10만 SKU 테스트 등은 실행 시간이 걸릴 수 있습니다.

## 코드 구조

| 경로 | 역할 |
| --- | --- |
| `crates/warehouse-core/src/` | Rust 계산·물류 상태·배정 코어 |
| `dist/` | 웹 UI, 3D 렌더러, 시뮬레이션 어댑터와 실행 파일 |
| `tests/` | 물류·재고·충돌·화면 회귀 검사 |
| `scripts/` | 로컬 서버, Wasm 빌드, 공급 효율 비교 |
| `docs/` | 모델 가정, Rust 전환 범위와 검증 결과 |

Vercel에서 자체 배포하려면 이 저장소를 가져오면 됩니다. 포함된 `vercel.json`은 `dist` 정적 파일을 배포하며, 별도 서버·API 키는 필요하지 않습니다. 원본 사이트의 프로젝트 연결 정보와 개인 첨부파일은 공유본에 포함하지 않았습니다. Pretendard 폰트의 원본 라이선스는 `dist/assets/Pretendard-LICENSE.txt`에 있습니다.

## 기능과 개발 기록

**v1.12.0 · Web + Rust와 폴더블 모바일 지원.** v1.2.0을 기준으로 주문·재고·빈 소유권,
포트 상태 전이와 작업 배정을 Rust·WebAssembly로 이전했습니다. 바닥 면적을
㎡ 또는 평으로 구성하고 셀 크기의 격자에 배치할 수 있으며, 기존 셀 수 제한을
제거했습니다. 선택 주문도 와이어프레임으로 추적하고 뷰 전환 시 카메라를 유지합니다.
[전환 범위·빌드·검증·후속 구조](docs/rust-migration.md)를 확인하세요.

개발: `npm run build` → `npm test` → `npm run dev`.
Rust 1.100.0과 Node.js를 사용하며 Rust JSON 파서는 잠긴 `json` 0.12.4 crate를 사용합니다. npm 의존성은 없습니다.

철물창고의 격자, 적층 빈, 로봇, 포트와 고객 주문을 함께 다루는 브라우저 기반 3D 시뮬레이터입니다. 현재 버전은 전체 화면 **시뮬레이션**, 별도의 **편집 모드**, 주문별 빈 강조와 완료 알림, 외장으로 가려진 3빈 포트, 유휴시간 빈 배치 최적화를 제공합니다. 기존 사이트의 같은 URL에서 갱신하는 정적 웹 앱입니다.

공개 치수와 실제 빈·재고의 이동을 적용하며, 공개 사양과 앱이 재구성한 기구·운영 가정은 [물리 모델과 적용 범위](docs/physical-model.md)에 구분해 기록합니다. 실물 장비, WCS 또는 OEM 컨트롤러와 연결하는 기능은 포함하지 않습니다.

## 공급 공백과 포트 빈 회수 개선 (v1.12.0)

일반 품목의 목록 순서 제약 없이 준비 시간과 포트 상태를 보고 배정합니다. 다음 빈은 먼저 들어 올려 대상 포트 가까운 안전한 위치로 이동하며, 포트 입구는 실제 인계할 때 예약합니다. 한 포트당 선행 운반은 1대, 전체는 가용 로봇 수보다 최소 1대 적게 유지합니다. 종료가 임박한 피킹에는 가까운 빈 로봇을 남겨 완료 빈을 먼저 회수합니다. 회수·디깅 빈은 다음 주문 빈을 다시 덮지 않는 가까운 저장 위치를 우선합니다.

기존 옵션은 **빈 선행 공급**으로 표시합니다. 켬/끔과 피킹 시간 설정을 유지하며, 이미 들고 있는 빈은 옵션 변경 후에도 안전하게 인계합니다. 긴급 승격된 선행 빈의 공간 확보와 단독 담당 로봇의 회수 책임을 검증합니다. 측정 정의를 그대로 유지한 전후 수치는 [공급 개선 검증](docs/order-prefetch.md)에 기록합니다.

## 자동 선행 리프팅·수량별 피킹·화면 계산 분산 (v1.11.0)

포트가 인계를 받을 수 없을 때도 다음 빈을 먼저 들어 올릴 수 있습니다. 남은 피킹 시간·다음 주문 수량·여유 로봇에 맞춰 준비량을 제한하며 회수할 로봇을 남깁니다. 3빈 포트의 후면 인계와 작업 위치의 피킹 시작은 병렬 진행합니다. 수량마다 물품 상승·스캔·반출을 반복하고, 주문/빈 추적의 강제 라벨을 없앴습니다.

시뮬레이션 계산을 프레임별로 분산하고 경로·주차 검증과 동적 그래픽 버퍼를 재사용합니다. 고부하에서는 요청 배속을 낮춰 따라가며 단일 배정 계산의 최악 실행시간을 보장하지는 않습니다.

**공급 빈 없음**과 **피킹 중단**은 서로 다른 지표입니다. 동일 6개 주문 비교에서 전체 완료와 실제 중단 시간은 감소했지만 공급 빈 없음 시간은 증가했습니다. 원인·정책·전체 비교 결과는 [자동 선행 준비 검증](docs/order-prefetch.md)을 확인하세요.

## 피킹 시간과 빈 선행 공급

**더보기 → 피킹과 선행 준비**에서 물품 1개당 시간을 **0.5~60초**로 설정합니다. UI 기본값은 **3초/개**이고 3·8·15초 빠른 설정을 제공합니다. 수량 2개라면 총 6초이며, 포트 회전·셔터·운반 시간은 별도로 유지됩니다. 진행 중에 시간을 변경하면 현재 피킹의 완료 비율을 유지하며 새 시간을 적용합니다. 설정은 브라우저에 저장되고 레이아웃 변경·작업 초기화 뒤에도 유지됩니다.

**빈 선행 공급**은 기본 켜짐이며 독립적으로 끌 수 있습니다. 일반 주문 품목의 목록 순서보다 준비·이동 시간과 포트 상황을 고려해 다음 빈을 미리 들어 가까이 대기합니다. 포트 입구는 인계 단계에서 예약하고, 회수 가능한 완료 빈을 먼저 빼냅니다. 긴급 주문 우선권과 이미 진행 중인 이송의 안전 조건은 유지합니다.

물류 이동이 피킹보다 느리면 대기는 남습니다. 특히 개당 시간을 짧게 설정할수록 공급이 병목이 될 수 있습니다. 모든 주문에서 처리시간이 줄어드는 보장은 없으며 비교 조건과 결과는 [선행 준비 검증](docs/order-prefetch.md)에 기록합니다. 피킹 시간·포트 전이·배정 선택은 Rust core 0.8.0/Wasm이 관리합니다.

## 편집 작업 공간 (v1.9.4)

평면 전체 맞춤은 실제 바닥·포트 경계와 가장자리 18px을 기준으로 배율을 계산합니다. 입체 전체 맞춤도 현재 방향의 3D 경계를 투영해 불필요한 거리 여유를 줄였습니다. 편집용 바닥판의 장식 여백도 축소했습니다. 일반 시뮬레이션 카메라는 유지됩니다.

**셀 확대**는 셀의 짧은 변을 최소 44 CSS px로 확대하며, 평면 **이동** 도구로 한 손가락 이동이 가능합니다. 기존 두 손가락 이동·확대도 지원합니다. **전체**는 확대·이동을 초기화해 전체 경계를 다시 보여줍니다. 전체를 한 화면에 표시할 때의 셀 크기는 그리드 크기에 따라 달라집니다.

편집 중 수용량은 상단바에 항상 표시됩니다. 설정창과 그리드는 서로 다른 화면 영역을 사용합니다. 넓은 화면은 좌우, 760px 미만 세로 화면은 상하로 나누며, 상단바·하단바 높이와 설정창 상태가 바뀌면 실제 캔버스 크기를 갱신합니다. 장면의 ResizeObserver가 투영과 입력 좌표를 함께 갱신하므로 창을 접거나 열어도 회전·이동·확대 상태는 유지됩니다.

설정을 열어 둔 상태로 셀 추가·삭제·포트 배치를 사용할 수 있습니다. 하단바는 배치 도구, 설정, 실행 취소·다시 실행, 종료·적용으로 정리했고 모바일은 두 줄입니다. 브러시·사각형·포트 종류와 평면·입체·전체 맞춤은 그리드 위에 있습니다. 설정은 독립 스크롤되며 접어도 편집 초안은 유지됩니다.

검증: 실제 CPU 렌더러에서 화면 맞춤 경계, 44px 셀 크기, 터치 이동 거리와 입력 좌표, 입체 경계 보존 및 위치와 종횡비가 달라진 캔버스의 동일 셀 배치, 카메라 조작 상태 보존, 작은 화면의 그리드 확장 버튼 위치를 확인했습니다. 브라우저에서는 데스크톱·390px 모바일·768px 폴더블·844px 가로 화면에서 비겹침, 설정을 연 채 사각형 삭제/배치·실행 취소, 설정 스크롤을 확인했습니다.

## 선택과 모달 렌더링 (v1.9.1)

일반·와이어프레임에서 셀을 배치하지 않은 바닥은 배경으로 취급하며, 편집 도구만 해당 좌표에 새 셀을 배치할 수 있습니다. 재고·주문·설정 모달과 네이티브 대화상자가 열리면 배경 3D의 데이터 변환·재그리기를 쉬고, Rust 시뮬레이션과 목록은 계속 갱신합니다. 모달을 모두 닫으면 최신 상태로 동기화합니다. 편집·셀/로봇 상세 패널은 장면을 계속 조작할 수 있으므로 이 제한에서 제외합니다.

대형 패널은 하나의 12px 블러 레이어를 쓰며 내부 헤더·푸터의 중첩 블러와 SVG 굴절 맵을 제거했습니다. 툴바의 굴절 맵은 최대 160,000픽셀로 제한합니다. 회귀 검증은 실제 CPU 렌더러에서 빈 바닥의 선택·호버 제외와 편집 배치, 20회 상태 변경 동안 0회 배경 재그리기 및 닫은 뒤 복귀를 확인합니다. 실제 Rust 작업을 구동하는 프레임 검증으로 모달 중 운용 지속·중첩 대화상자·일시정지 보존도 확인합니다. 브라우저에서는 데스크톱과 390px 화면의 목록 스크롤·닫기·현재 상태 복귀를 확인했습니다. 기기별 FPS 수치는 측정하지 않았습니다.

## 로봇 운용 전략 (v1.6.0)

더보기 → **로봇 운용 전략**에서 완료시간 기반 배정, 포트 흐름 조율, 시간대별 경로 예약을 각각 켜거나 끌 수 있습니다. 웹 UI는 처음에 세 옵션을 켜며 선택을 브라우저에 저장합니다. 선행 준비까지 모두 끄면 기본 배정으로 돌아갑니다. 진행 중인 작업은 마무리하고 다음 배정부터 변경합니다. 그리드, 속도, 로봇 대수, 포트와 초기 재고 배치는 바꾸지 않습니다.

후보 작업의 점수 계산, 시간 예약 충돌 검증과 배정 승인은 Rust/Wasm이 수행합니다. 경로·동작 후보와 점유 시간 구간은 웹 어댑터가 생성합니다. 유휴시간 재배치는 기존의 별도 옵션입니다. 운용 지표는 현재 실행의 누적값이므로 비교할 때 같은 주문으로 실행을 초기화하세요. 전략별 효과와 한계는 [운용 전략 검증](docs/robot-strategies.md)에 기록했습니다.

모달은 내용에 맞게 줄이고 화면에 여백을 남깁니다. 재고·주문·포트 목록, 선택 작업 바를 반투명 유리 색상으로 통일하고 모바일 목록은 패널 안에서 한 번만 세로 스크롤됩니다.

## 선택과 기구 표현 (v1.9.0)

로고·운영 상태·재고/로봇/주문 현황·메뉴는 하나의 글라스 상단바에 통합했습니다. 넓은 화면은 한 줄, 폴더블과 휴대폰은 두 줄로 배치하며 상시 카메라 조작 안내는 숨겼습니다.

셀·로봇을 누르면 카메라를 유지한 채 임시 와이어프레임으로 전환합니다. 배경 클릭·닫기·Escape로 선택을 해제하면 기존 뷰로 돌아오며, 주문·재고 추적이 이미 켜져 있었다면 해당 추적을 유지합니다. 선택 상세창 바깥에서 카메라를 회전할 수 있습니다. 선택한 로봇의 실제 배정 빈은 금색으로 표시하고, 운반 중에는 그 빈을 표시합니다. 대기 로봇에는 임의의 목적지를 만들지 않습니다. 선택 로봇의 다음 이동 구간은 초록 경로·방향 화살표로 표시하며, 실제 예약 경로의 남은 구간만 사용합니다. 호이스트 동작 중에는 다음 이동 구간을 표시하고, 선택 해제 시 경로를 지웁니다.

3빈 포트의 대기 빈이 접근할 때 실제 회전각 80%에서 뚜껑을 열기 시작하며, 피킹은 회전 정지·0.35초 안착·완전 열림 후에만 시작합니다. 닫힘은 회전 시작과 동시에 진행합니다. 상단 커버는 95% 불투명입니다. 바닥과 포트 전면에 공식 심볼·워드마크를 배치했습니다. 로봇 본체 상단은 번호만, 왼쪽 측면은 번호, 오른쪽 측면은 심볼을 표시하고 장식 점을 제거했습니다. 주행 방향에 따라 비활성 바퀴 쌍이 최대 18mm 올라갔다 내려오며, 완전 복귀한 리프트 상판은 레일 위 640mm의 본체 지붕과 맞춰집니다.

## 호버와 빈 내부 표현 (v1.8.1)

마우스를 올리면 그 열의 실제 빈 전체에 22% 반투명 음영과 옅은 층 테두리가 나타납니다. 클릭한 셀은 더 선명한 초록색을 유지하고, 추적 빈의 빨간색은 호버보다 우선합니다. 포인터가 떠나거나 드래그·확대를 시작하면 미리보기를 지우며, 터치 이동으로는 호버를 남기지 않습니다. 편집 브러시의 추가·삭제 피드백은 유지합니다.

빈 내부는 물리적인 칸막이가 없는 하나의 열린 공간으로 표시합니다. SKU의 논리적 구획과 재고 관리는 그대로 사용합니다. 와이어프레임에서는 추적 빈·리프터 상판·벨트·피킹 물품이 동일한 깊이 기준으로 그려져, 빈이 위쪽 리프터 상판을 덮지 않습니다.

## 포트와 셀 선택 (v1.8.0)

일반 1빈 포트는 같은 자리에서 수직 인계하고 전면 작업창을 통해 피킹하는 구조입니다. 롤업 셔터는 작업자 쪽 전면에서 열리고 닫히며, 로봇이 빈을 내리는 통로는 가로막지 않습니다. 작업 화면과 고정 바코드 리더기는 승강 경로 밖에 있습니다. 외곽 설치 면적과 1빈 수용량은 유지합니다.

물품은 빈 안에서 올라와 리더기 앞에 멈추고, 라벨을 스캔한 뒤 녹색 인식 표시와 함께 작업자 방향으로 반출됩니다. 요청 진행률에 맞춘 1회 연출이며 물품의 크기는 고정됩니다. 실제 수량·바코드 판독이나 하드웨어 연동은 수행하지 않습니다. 일시정지·속도·동작 줄이기 설정과 일반/와이어프레임에 함께 적용합니다.

셀을 선택하면 현재 그 열에 보관된 모든 빈의 몸체와 각 층 테두리가 초록색으로 강조됩니다. 이동 중인 빈은 선택 열에 남겨 그리지 않으며, 와이어프레임에서 추적 중인 빈은 빨간색을 유지합니다. 빈이 없는 셀은 기존 위치 테두리로 표시합니다.

## 화면과 피킹 표현 (v1.7.0)

작업 초기화는 시작·일시정지 바로 옆의 회전 화살표 버튼입니다. 같은 주문 정의와 레이아웃을 유지하고 재고·실행을 초기화합니다. 모바일에서는 상단 더보기와 중복되는 하단 설정 버튼을 숨겨 초기화까지 44px 터치 영역을 확보합니다.

전체 그리드·전체 빈·디깅 맞춤과 입체/정면 버튼은 실제 포트의 작업자 방향을 기준으로 카메라를 배치합니다. 여러 방향의 포트는 슬롯 수를 가중치로 합산하고, 서로 상쇄되면 주 포트 방향을 사용합니다. 주문 추적 시작과 와이어프레임 해제는 기존처럼 카메라를 유지합니다.

피킹 중인 빈에서는 위의 스캔·반출 연출을 표시합니다. 재고 수량과 다른 장식용 표현이며 실제 요청의 진행률을 사용해 일시정지·속도 변경과 함께 움직입니다. 창이 닫혔거나 피킹이 끝나면 표시하지 않고, 동작 줄이기 환경에서는 고정 표시합니다. 일반/와이어프레임 및 WebGL/CPU 렌더러에 적용합니다. 리프트의 그리퍼는 중앙이 막힌 상판과 공식 WEDRAW 심볼을 사용하며 기존 네 벨트·승강·체결 위치를 유지합니다.

## 화면과 조작

기본 화면 이름은 **시뮬레이션**입니다. 3D 뷰를 전체 화면으로 유지하고, 재고·주문·포트·설정은 필요한 때 떠 있는 패널로 엽니다. 상단에는 SKU·작업 로봇·출고 주문의 핵심 지표, 하단에는 실행·속도·화면 맞춤을 배치합니다. 상세 통계와 구조 보기 설정은 더보기 안에 있습니다.

| 영역 | 조작과 기능 |
| --- | --- |
| 시뮬레이션 | 왼쪽 클릭 드래그로 회전, 휠로 확대·축소. 전체 그리드 맞춤, 입체·평면·정면 보기 |
| 재고 | 최대 10만 SKU 검색·필터, 빈·구획·가용 상태 확인, 와이어프레임 빈 추적, SKU 추가·개수 축소·선택 삭제, CSV 내보내기 |
| 주문 | 단품·합포장 생성, 목록에서 주문 선택·우선 처리·일반 실행·빈 추적, 피킹 진행, 일괄 실행, CSV 내보내기 |
| 편집 | 초안 편집, 최대 SKU·증감, 브러시·사각형, 포트 미리보기·이동, 실행 취소·다시 실행, 적용·취소 |
| 포트 | 포트별 3빈 버퍼 현황, 스테이션 전체 보기, 작업자 시점 |
| 더보기 | 피킹 시간·빈 선행 공급, 로봇 운용 전략 3종, 표시 옵션, 유휴시간 자동 최적화, 실행 통계, 작업 기록, 설계 파일, 사용 방법 |

편집 메뉴를 열면 시뮬레이션을 일시정지하고 별도의 편집 초안을 만듭니다. 설정 패널을 닫아도 편집 모드는 유지됩니다. **변경 적용**에서 용량·포트·운영 조건을 검토한 뒤 한 번만 실제 설계를 재구성하며, **편집 취소**는 원래 재고·빈 위치·주문·실행 시점을 유지하고 이전 실행 여부를 복원합니다. 편집 도중에는 운영 재생 도크 대신 편집 도구를 표시합니다.

### 편집 초안과 수용량

상단의 최대 수용 SKU는 엔진이 계산한 저장 가능 빈 수에 빈당 구획 수를 곱한 값입니다. 포트 설비 영역, 2칸 로봇·상부 대기 위치로 인해 출고 접근이 불가능한 열, 디깅 여유 공간을 제외하며 구획당 SKU 한 종류를 가정합니다. 현재 등록 SKU, 남은 용량 또는 부족량, 편집 전 대비 증감을 함께 표시합니다. 보관 수용량과 현재 재고의 출고 가능 여부는 구분하며, 포트·2셀 로봇 경로가 막힌 경우 별도 안내합니다. 기본 12×8·8층·4구획 설계는 2,256 SKU를 수용합니다. 포트 외장과 인계 타워의 실제 점유 열 10개를 제외한 값입니다.

셀은 브러시 또는 사각형으로 미리 보고 놓을 때 한 번 반영합니다. 한 드래그와 한 높이 슬라이더 조작은 각각 실행 취소 한 단계입니다. Ctrl/Cmd+Z로 취소, Ctrl/Cmd+Shift+Z 또는 Ctrl+Y로 다시 실행합니다. 위에서 편집은 정투영과 단순한 셀 표시를 사용합니다. 외곽 +행/+열 버튼에 올리면 용량 변화를 미리 보고 범위를 확장할 수 있습니다.

포트는 전체 스테이션, 샤프트, 작업자 방향과 설비 점유 영역을 미리 표시합니다. 초록은 설치 조건 충족, 노랑은 보관 설계는 가능하나 운영 조건 확인 필요, 빨강은 중복·설비 충돌로 배치 불가를 뜻합니다. 기존 포트 클릭은 선택이며, 선택한 포트는 드래그 또는 이동 버튼으로 ID를 유지해 옮깁니다. 삭제는 별도 버튼과 실행 취소로 처리합니다. **편집 종료**는 변경 여부와 관계없이 항상 사용할 수 있습니다. 변경이 없으면 시뮬레이션을 다시 만들지 않고 기존 실행·일시정지 상태로 돌아갑니다. Esc는 열린 패널을 먼저 닫고, 패널이 닫힌 상태에서는 편집을 종료합니다. 변경이 있으면 계속 편집, 변경 취소하고 종료, 변경 적용 중 하나를 선택합니다.

편집 설정 하단에 변경 상태와 **편집 종료 / 변경 적용** 버튼이 항상 표시됩니다. 변경이 없으면 적용 버튼만 비활성화됩니다.

일반 패널은 닫기 버튼·바깥 클릭·Esc로 닫습니다. 알림·완료 메시지와 확인창도 바깥 클릭으로 닫습니다. 적용·삭제 확인창의 바깥 클릭은 작업을 실행하지 않고 창만 닫습니다. 모바일에서는 패널이 하단 시트로 바뀌고, 화면의 안전 영역과 좁은 폭에 맞춰 도크와 메뉴를 줄입니다.

### UI 형태 규격

`dist/shape-system.css`에서 모서리와 컨트롤 크기를 관리합니다. 기본 버튼·입력창은 R8, 보조 소형 버튼은 R6, 도구 모음 내부와 그룹은 R10입니다. 바깥 도구 모음은 R16(좁은 화면 R14), 떠 있는 카드는 R14, 큰 패널은 R18(모바일 R16)로 반경을 줄였습니다. 닫기는 원형, 상태 배지는 R6, 진행 막대는 캡슐형으로 역할을 구분합니다. 일반 컨트롤 높이는 40px, 터치 환경과 주 도구 모음은 44px입니다. 이 값은 브랜드 가이드의 지정값이 아닌 앱의 UI 규격입니다.

### 브랜드

흰색·중성 회색 중심의 프로스티드 글라스 UI에 제공된 WEDRAW 브랜드 가이드를 적용했습니다. 메뉴·도크에는 투명한 틴트와 굴절 렌즈, 가장자리 빛 반사를 사용합니다. Chromium 계열에서는 SVG 변위 맵이 실제 배경을 가장자리에서 굴절시키며, 글자·로고·터치 영역은 변형하지 않습니다. 지도는 크기가 바뀔 때만 생성합니다. 다른 브라우저는 투명도·블러·반사 테두리로 표시합니다. 주문·재고 목록은 더 강한 블러와 밝은 틴트로 읽기 쉽게 했습니다. 딥그린은 주요 실행·선택 상태와 공식 로고에 포인트로 사용합니다. 투명도 감소 설정과 블러 미지원 환경에서는 단색 패널로 표시합니다. 로봇은 아이보리 본체 패널과 차콜 상·하부의 투톤입니다. 밝은 면에는 브랜드 녹색 로고와 차콜 번호, 어두운 면에는 흰색 로고와 번호를 사용합니다. 상판·양측·정면의 001·002처럼 큰 세 자리 번호와 공식 로고 벡터는 차체 표면에 붙어 이동하며 화면의 로봇 따라보기 이름과 일치합니다. 디깅 추적 시에도 본체 투톤을 유지하고 민트 윤곽선·상태 표시·라벨로 담당 로봇을 구별합니다.

- 공식 로고와 심볼은 제공된 PDF의 벡터 경로에서 추출했습니다. 원래의 형태·비율·간격·색을 유지하고, 제품 표기는 **wedraw WMS**를 사용합니다.
- 주요 색은 Deep Green `#215732`, Pistachio `#DDEBCB`입니다. 읽는 영역에는 중성 회색과 흰색을 사용합니다.
- UI 서체는 가이드의 **Pretendard**이며 폰트 파일을 자체 호스팅합니다. [SIL Open Font License 원문](dist/assets/Pretendard-LICENSE.txt)을 함께 배포합니다.
- 자산 출처와 색상 기록은 [brand-sources.txt](dist/assets/brand-sources.txt)에 있습니다.

3빈 포트는 라운드 서비스 도어·매립 손잡이·통풍구, 금속 상판, 승강 타워 이음새, 작업 콘솔을 갖습니다. 곡선 외장은 연속 다각 곡면으로 만들고, 상판은 구멍을 제외한 겹치지 않는 면으로 구성합니다. 타워 모서리의 중복 면을 제거했으며 와이어프레임은 같은 곡선 외곽과 구조선을 사용합니다. 회전대와 셔터는 실제 포트 동작 상태를 따릅니다. 외장 점유 범위와 내부 빈 회전·인계 간격은 기존 물리 모델의 제약을 유지합니다.

## 빠른 사용 순서

1. **편집**에서 먼저 바닥 면적(㎡/평) 또는 가로·세로 길이를 정합니다. 바닥 적용 후 셀 크기 격자 위를 사각형 또는 브러시로 드래그해 배치하고, 공통 적층 높이·빈 규격·포트를 정합니다. 포트 설치 조건에 맞지 않는 배치는 표시되며, 낮은 그리드를 운영 가능한 것처럼 처리하지 않습니다. 상단 수용량을 확인하고 **변경 적용**에서 최종 반영합니다.
2. **재고 → 전체 SKU 수 조절**에서 목표 수를 입력하거나 `+100`, `+500`, `+1,000`, `+10,000`을 누릅니다. 줄이면 뒤쪽 품목부터 삭제 대상을 확인하고, 체크박스로 선택한 품목만 삭제할 수도 있습니다. 추가 용량이 부족한 품목은 미배정으로 남습니다.
3. **주문 → 더미 주문 만들기**에서 생성 건수와 합포장 비율을 정합니다. 현재 재고와 예약 수량을 고려해 단품·합포장 주문을 생성합니다.
4. 주문 한 건을 선택합니다. 시뮬레이션 화면으로 돌아가 해당 주문의 SKU가 들어 있는 실제 빈들을 강조하며, 선택 카드에 SKU·빈·수량과 피킹 진행을 표시합니다.
5. **선택 주문 실행**을 누릅니다. 선택 주문만 새로 제출하며, 전체 대기 주문을 일괄 제출하지 않습니다. 전체 주문을 처리하려면 주문 패널의 **대기 주문 실행**을 사용합니다.
6. 포트의 **작업자 시점**으로 접근창 앞에서 한 개씩 제시되는 빈을 관찰합니다. 선택 주문의 모든 구성품이 실제로 피킹되면 완료 알림과 폭죽이 한 번 표시됩니다.
7. 주문이 없는 동안에도 시뮬레이션을 계속 실행하면, 켜져 있는 **유휴시간 자동 최적화**가 고객 주문 수요를 바탕으로 빈 배치를 개선합니다. 일시정지를 누르면 모든 이동과 포트 동작을 멈춥니다.

**같은 주문 다시 실행 준비**는 재고·실행 기록을 초기화하고 주문 정의를 대기 상태로 되돌립니다. **디깅 시연**도 실행을 초기화한 뒤 깊은 빈 한 개의 반출을 보여줍니다. 주문을 선택해 보는 행위 자체는 재고를 변경하거나 피킹 요청을 제출하지 않습니다.

## 그리드와 철물 재고

- 바닥을 ㎡/평 또는 실제 길이로 구성합니다. 셀은 705×480mm이며 바닥 끝의 나머지 길이도 표시합니다. 직사각형·L자·U자·직접 그리기를 사용할 수 있고 바닥을 늘려도 새 셀이 자동으로 채워지지 않습니다.
- 기존 24셀 변 길이·768셀 총량 제한을 제거했습니다. 실제 가능한 크기는 브라우저 메모리·렌더링 성능과 Wasm 셀 주소 범위에 따릅니다.
- 모든 열에 같은 적층 높이를 적용합니다. 1층 높이부터 최대 6m까지 입력할 수 있으며, 빈 규격별 최대 적층 수를 함께 적용합니다.
- 빈 높이는 220/330/425mm입니다. UI 구획 수는 1/4/8/16이며, 425mm 빈은 공개 구획 상한에 맞춰 최대 8구획으로 제한합니다.
- 고유 코드가 있는 철물 1,000 SKU로 시작하고 전체 품목 수를 0~100,000 SKU로 조절할 수 있습니다. 경첩, 피스, 연결철물, 브래킷, 손잡이, 레일, 다보 등 10개 분류를 사용합니다.
- SKU 추가·삭제는 남은 코드·품목·수량·구획·빈 위치·피킹 결과를 유지합니다. 로봇 작업과 포트의 빈이 정리되고 정지한 상태에서 수행하며, 삭제 대상에 접수된 미완료 요청이 있으면 삭제하지 않습니다. 삭제 확인에는 연결 주문을 표시하고, 삭제된 SKU가 포함된 미완료 주문은 보류합니다. 빈이 비어도 물리 빈은 유지하며 재추가 시 빈 구획을 활용합니다. 새 SKU는 이전에 사용한 번호를 재사용하지 않습니다.
- 빈당 최대 적재 하중 30kg 안에서 더미 수량을 구성합니다. 철물의 실제 3차원 형상에 대한 정밀 적재 계산은 하지 않습니다.
- 설비 설치 영역에 해당하는 열은 저장 공간에서 제외하고, 연결 구역별로 디깅 재배치 공간을 남깁니다. 배정되지 않았거나 운영 가능한 포트 경로가 없는 SKU를 구분합니다.

층수는 설정 높이와 명목 빈 높이의 비율에 빈 규격별 적층 상한을 적용해 정합니다. 예를 들어 220mm 빈에 6m를 입력해도 27층으로 만들지 않습니다. 화면의 실제 적층 높이는 명목 적층 높이이며, 상부 로봇·건물 천장·정비 여유까지 포함한 설치 전체 높이가 아닙니다.

1층 그리드도 편집·보관 수용량·재고 확인은 가능합니다. 포트 운영에 필요한 최소 높이와 설치 조건은 별도로 검사합니다. 구체적인 최소 층수, 빈 치수, 외곽 공간과 조건은 [물리 모델 문서](docs/physical-model.md)를 따릅니다.

출고 접근 불가 열은 초기 빈 배정, SKU 추가, 디깅 재배치, 빈 복귀 및 자동 최적화의 목적지에서 제외합니다. 수용량을 넘는 SKU는 미배정으로 남습니다. 포트가 없는 구역도 빈을 배정하지 않으며, 설계를 적용하거나 다시 불러올 때 새 접근 조건으로 재계산합니다. 운영 중 모든 경로 교착을 없애는 전역 교통 제어를 뜻하지는 않습니다.

## 주문 선택, 강조와 출고

단품 주문은 SKU 1종, 합포장은 2~5종으로 구성합니다. 대기 주문과 미피킹 요청이 예약한 수량을 차감한 가용 재고에서 더미 주문을 만듭니다. 주문별·SKU별 예약 수량, 실제 피킹 수량, 담당 로봇과 포트를 확인할 수 있습니다.

목록의 **주문 선택**은 화면 이동 없이 하단 작업 바를 엽니다. **우선 처리**는 Rust에서 합포장 전체의 미완료 요청을 승격하며, 진행 중인 작업·빈 소유권을 유지하고 요청을 중복 생성하지 않습니다. 이미 대기 중인 우선 요청 다음 순서로 배정합니다. **빈 추적**은 와이어프레임으로 이동합니다. 모바일은 한 세로 스크롤 흐름을 사용하며 터치·관성 스크롤 중 행을 교체하지 않습니다.

선택 주문의 강조 대상은 좌표가 아닌 **빈 ID**입니다. 빈이 저장 열에서 로봇으로 이동하고 포트로 인계되어도 같은 물리 빈을 추적합니다. 여러 SKU가 같은 빈에 들어 있으면 그 빈을 한 번만 강조하며, 미배정 SKU는 선택 카드에 표시합니다.

주문목록에서 주문을 선택하거나 현재 반출 작업 목록에서 주문을 추적할 때 카메라 위치·회전·확대·이동을 유지합니다. 로봇·포트를 따라보던 경우에는 그 시점을 고정하고 와이어프레임으로 전환합니다. **전체 빈 맞춤**, 개별 빈 위치 맞춤, **디깅 함께 보기**를 직접 누르면 해당 대상을 화면에 맞춥니다.

합포장 구성품 일부가 준비되면 합포장 대기 상태가 됩니다. 모든 SKU 라인의 요청 수량이 실제로 피킹되어야 출고 완료와 한 포장으로 집계합니다. 빈 인양이나 포트 도착만으로 완료 처리하지 않습니다. 피킹 완료 뒤에도 빈의 그리드 복귀가 진행될 수 있습니다.

폭죽은 **선택한 주문의 확인된 피킹 완료**에 한 번 발생합니다. 이미 출고된 주문을 다시 선택해도 재생하지 않습니다. 효과는 짧게 끝나는 로컬 캔버스 애니메이션이며 소리를 재생하지 않습니다. `prefers-reduced-motion: reduce`에서는 폭죽을 생략하고 완료 메시지로 결과를 알립니다. 포장 박스의 컨베이어 이동이나 운송은 계산하지 않습니다.

## 로봇과 협업 디깅

로봇은 AutoStore R5/R5+의 공개 외형을 참고한 인양 셀과 인접 구동 셀의 **1×2셀** 모델입니다. 차체는 항상 그리드 상부 레일에 머물고, X/Y축 이동 시 차체 방향을 유지합니다. 대기 로봇도 레일에 남으며, 두 칸을 확보하지 못하면 미배치로 표시합니다.

네 벨트의 상단은 차체에 고정하고 하단은 수평 그리퍼에 연결합니다. 빈 인출은 빈 없는 그리퍼 하강 → 체결 → 빈 인양, 적재는 빈 하강 → 해제 → 빈 없는 그리퍼 복귀 순서입니다. 체결·해제 시점에 빈 소유권이 바뀌며, 빈이 사라졌다가 다른 위치에 나타나는 전환을 피합니다.

수직 이동에는 시작과 끝의 속도·가속도가 0인 `6t⁵−15t⁴+10t³` 곡선과 거리 기반 시간을 적용합니다. 로봇·그리퍼·빈·벨트의 위치를 같은 동작 단계에서 계산합니다. 이 값은 앱의 동작 가정이며 현장 장비의 실측 성능값이 아닙니다.

깊은 빈을 꺼낼 때는 상부 빈 재배치, 목표 빈의 포트 인계, 피킹 후 회수를 별도 작업으로 배정합니다. 협업 디깅은 앞선 로봇이 인출 열을 완전히 벗어나면, 해당 빈의 운반·적재·복귀가 끝나기 전에도 다른 로봇이 다음 상부 빈을 인출하는 방식입니다. 같은 열 안에서의 승강은 한 대씩 진행하며, 운반과 다른 열에서의 작업을 겹칩니다. 실제 상부 빈을 운반한 로봇만 협업 참여자로 집계하고, 동일 요청을 여러 대가 동시에 작업할 때 화면에 **협업 디깅 중**과 참여 대수를 표시합니다.

작업별로 필요한 두 칸 경로를 예약하고 대기 로봇도 장애물로 취급합니다. 주행 중인 두 칸과 앞으로 사용할 경로는 보호하고, 완전히 지나가 다시 사용하지 않을 경로는 순차적으로 해제합니다. 독립 경로를 확보한 작업은 병행하며, 통로가 겹치거나 재배치 공간이 부족하면 기다립니다. 실제 OEM 컨트롤러의 전체 교통 최적화, 양보 주행, 충전·배터리 운영까지 재현하지는 않습니다.

## 외장이 있는 3빈 포트

3빈 포트는 외장, 작업대, 접근창, 후면 하우징과 내부 회전 기구를 가진 스테이션으로 표현합니다. 기본 외장 보기와 **작업자 시점**에서는 앞에 제시된 빈 한 개를 볼 수 있습니다. 나머지 두 빈은 외장 안에서 대기·교환·회수되며, 더보기의 **스테이션 내부**를 켜면 내부 구조를 확인합니다.

두 후방 로봇 인계점과 한 전방 작업점을 세 개의 회전 트레이로 연결합니다. 로봇은 후방 트레이에 직접 빈을 내려놓거나 회수합니다. 작업창이 닫혀 있고 인계가 끝난 상태에서 회전하며, 트레이가 멈추고 안착한 뒤 접근창이 열립니다. 완전히 열린 상태에서만 실제 피킹 수량을 차감합니다.

포트는 입고 예약을 포함해 총 3자리를 제한하고 한 번에 한 빈만 피킹합니다. 빈은 항상 그리드·로봇·포트 중 한 곳에만 속합니다. 설치 영역에는 저장 빈을 배정하지 않으며, 작업자 전면 접근이나 후방 인계점이 확보되지 않거나 포트 설치 영역이 서로 겹치면 운영 불가 이유를 표시합니다.

전면 가구의 공개 치수, 후방 기구를 위해 앱이 정한 영역, 재구성한 회전 반경·인계점 간격은 서로 구분합니다. 자동 접근창 동작 또한 앱의 차폐·피킹 조건 모델입니다. 실제 CarouselPort의 안전 제어 방식, OEM CAD 또는 설치 승인 도면과 같다고 주장하지 않습니다. 출처와 수치, 남은 실측 보정 사항은 [물리 모델과 공개 사양의 적용 범위](docs/physical-model.md)에 정리되어 있습니다.

## 유휴시간 자동 최적화와 상태 표시

**유휴시간 자동 최적화**는 앱에서 기본으로 켜집니다. 현재 고객 주문 정의를 바탕으로 각 빈의 요청 빈도를 계산합니다. 한 주문 안의 여러 SKU가 같은 빈을 요청해도 해당 빈의 수요는 **주문당 한 번**만 더합니다. 철물 수량을 그대로 빈 요청 횟수로 세지 않습니다.

고객 요청이 없는 유휴시간에는 자주 요청된 빈의 접근 깊이를 줄이는 재배치를 시도합니다. 새 고객 요청을 우선 처리하며, 이미 시작한 빈 이동은 안전한 인계·적재 단계까지 마무리합니다. 개선 가능한 이동이 없으면 계속 빈을 흔들거나 불필요한 순환을 만들지 않고 운영 대기로 남습니다.

스위치를 끄면 새 최적화 작업을 배정하지 않고 진행 중인 빈 이동을 마무리합니다. **일시정지**는 이와 달리 로봇 이동·승강·포트·최적화를 모두 멈춥니다. 다시 실행하면 중단한 동작을 이어갑니다.

화면의 시스템 상태는 디깅 중, 빈 운반 중, 유휴시간 최적화 중, 대기 중 등의 현재 작업과 한 줄 설명을 표시합니다. 운영 준비·일시정지·설치 조건 확인·편집 상태도 구분합니다. 상세 통계에는 완료된 최적화 재배치 수와 수요 계산에 사용한 주문·빈 수를 표시합니다. 자동 최적화는 공개 제품의 특정 알고리즘을 복제한 것이 아니라 이 앱의 주문 빈도 기반 정책입니다.

## 재고에서 우선 반출

철물 재고의 **1개 우선 반출**은 일반 고객 주문과 유휴 최적화보다 높은 우선순위로 접수합니다. 버튼을 누르면 시뮬레이션을 시작·재개하고, 해당 빈을 와이어프레임 화면에서 빨간색으로 추적합니다. 기존 예약을 제외한 가용 재고가 있어야 접수할 수 있습니다.

우선 요청이 남아 있는 동안 새 일반 반출과 최적화의 배정을 보류합니다. 이미 시작한 빈 이송·승강과 포트 피킹은 마무리하며, 같은 빈의 선행 작업이나 포트 자리를 확보하는 데 필요한 복귀는 계속할 수 있습니다. 로봇이 빈을 들고 있는 도중 소유권이나 목적지를 바꾸지 않습니다. 여러 우선 요청은 접수 순서대로 배정합니다.

시스템 상태는 **우선순위 반출 중**으로 바뀌고, 대상 빈과 디깅·포트 운반·피킹·빈 복귀 단계 또는 실제 대기 사유를 표시합니다. 작업 기록에서도 **최우선** 배지로 구별합니다. 일시정지하면 우선 요청을 유지하고 정지 상태를 표시합니다. 요청한 수량의 피킹과 빈 복귀를 마치면 일반 주문, 이후 유휴 최적화를 이어갑니다.

## 작업을 마친 로봇의 다음 배정

빈을 내려놓고 빈 없는 그리퍼가 상부까지 올라오면 그 위치에서 이송을 마칩니다. 다음 작업은 실제 현재 위치에서 인출 지점까지의 경로 거리로 배정하며 매번 고정 주차점으로 돌아가지 않습니다. 다른 로봇의 인출·포트 진입과 2셀 통로를 막을 때에만 가까운 안전 위치로 비킵니다. 진행 중인 다른 로봇들의 종료 위치까지 함께 확인하여 이후 접근 가능성을 유지합니다. 이는 충돌과 접근성을 보존하는 휴리스틱이며 전역 최적 스케줄을 보장하지 않습니다.

편집 설정의 **로봇 수**를 직접 입력하거나 ± 버튼으로 **1~30대**를 요청할 수 있습니다. 실제 배치는 2셀 점유와 경로 접근 조건을 따릅니다. 설정 화면은 요청 수와 배치 가능 수를 구분하고, 공간이 부족한 로봇은 격자 밖에 억지로 놓지 않고 미배치로 표시합니다.

## 운영 상태에서 현재 반출 확인

왼쪽 **운영 상태 창**은 현재 작업 목록을 여는 버튼입니다. 목록은 주문, 상태·현재 단계, 피킹 진행, SKU·빈, 담당 로봇·포트를 정렬한 행 형태이며, 행 전체를 클릭하거나 Enter·Space로 상세를 엽니다. 접수한 고객 주문과 재고에서 낸 개별 반출을 주문 단위로 묶어 보여주며, 우선 반출을 맨 앞에 표시합니다. 진행 중·배정 대기·우선 반출 수, 요청 수량과 피킹 수량, 현재 단계, 담당 로봇·포트와 대기 사유를 실시간으로 갱신합니다. 보류된 요청은 사유를 유지하고, 빈 복귀까지 완료한 작업은 현재 목록에서 빠집니다.

주문의 **상세 · 빈 보기**를 누르면 모달이 닫히고 해당 주문의 모든 물리 빈을 빨간색으로 동시에 추적합니다. 창고는 와이어프레임으로 표시하며, 디깅이 필요한 상부 빈과 담당 로봇은 아래의 디깅 추적 규칙으로 구별합니다. 여러 SKU가 같은 빈에 있으면 한 번만 표시하고, 일부 SKU의 피킹이 먼저 끝나도 주문에 포함된 원래 빈을 유지합니다. 각 빈의 실제 셀·층, 운반 로봇 또는 포트 위치를 확인하고 **전체 빈 맞춤**이나 개별 빈 위치 버튼으로 카메라를 맞출 수 있습니다.

상세 카드의 **SKU별 진행과 담당 로봇**을 펼치면 품목, 피킹 수량, 단계, 포트와 현재 로봇 동작을 확인합니다. 디깅 중이면 로봇이 현재 옮기는 상부 빈도 구별합니다. **작업 목록**으로 다른 주문을 선택하거나 **추적 종료 / Esc**로 일반 화면에 돌아갑니다. 조회와 위치 선택은 반출 순서·수량·시뮬레이션 실행 상태를 변경하지 않습니다.

현재 반출 요청이 없는 유휴 최적화도 운영 상태와 **로봇 · 포트 현황**에서 어떤 빈을 옮기는지 확인할 수 있습니다. 실제 경로 문제가 생겨 정지한 경우에는 완료로 표시하지 않고 **경로 확인 필요**로 표시합니다.

## 재고의 빈 위치 추적

철물 재고에서 **SKU 코드, 빈 번호, 현재 위치** 중 하나를 누르면 패널을 닫고 해당 물리 빈을 추적합니다. 그리드와 나머지 창고는 와이어프레임으로 바뀌고, 선택한 빈은 빨간 실체로 표시합니다. 적층 내부나 포트 외장에 가려져도 대상 빈은 보이며, 저장 중인 열은 붉은 셀 윤곽으로 구별합니다.

카드는 빈 ID, SKU·구획, 실제 셀과 층수 또는 담당 로봇·포트, 작업 상태와 남은 수량을 표시합니다. 선택은 실제 빈 ID에 연결되어 디깅·인양·운반·포트 피킹·복귀 중에도 같은 빈을 추적합니다. SKU 수량이 0이 되어도 물리 빈이 존재하면 추적을 유지합니다. **빈에 맞춤**은 카메라를 다시 맞추며 왼쪽 드래그 회전은 계속 가능합니다. **재고 보기**로 목록에 돌아가거나 **추적 종료 / Esc**로 컬러 화면을 복원합니다.

추적 선택 자체는 재고·주문이나 실행 상태를 바꾸지 않습니다. 편집 진입·실행 초기화·선택 SKU 삭제·다른 주문 또는 로봇/포트 보기로 전환하면 추적을 해제합니다. 미배정 SKU는 실제 빈이 없어 추적 버튼을 표시하지 않습니다.

### 디깅이 보이는 빈 추적

재고의 단일 빈과 주문의 여러 빈 추적 모두에서 **목표 빈은 빨강, 그 위의 상부 빈은 회색 실체, 실제 디깅 담당 로봇은 청록 강조**로 구별합니다. 일반 빈에는 옅은 청회색 반투명 면 음영과 윤곽선을 함께 적용해 상자 형태와 층을 구분하고, 레일·포트 외장·비관련 로봇은 와이어프레임으로 유지합니다. 배경 음영은 목표 빈·상부 빈·담당 로봇을 가리지 않습니다. 상부 빈은 실제 `cell.stack`에서 목표보다 위에 있는 빈만 계산하며, **남은 상부 빈**과 목표별 라벨에 개수를 표시합니다. 여러 목표의 상부 빈이 겹치면 합계에서는 중복을 제외합니다. 다른 선택 목표가 위에 쌓여 있다면 개수에는 포함하지만 목표 색상인 빨강을 유지합니다.

일반 빈은 전면에서 보이는 윤곽을 중심으로 표시하고 가려진 뒷면 선을 정리합니다. 레일과 포트 등의 배경선은 낮은 대비로 표시합니다. 회색 디깅 빈과 담당 로봇은 독립된 강조 영역으로 그려 배경선이 실체 위를 가로지르지 않으며, 빨간 목표 빈은 마지막 투시 표현으로 유지합니다. 실제 빈 위치·크기·적층 간격은 바꾸지 않습니다.

로봇이 상부 빈을 체결해 적층에서 실제로 들어 올리면 남은 개수가 줄고, 그 빈은 **운반 중**으로 따로 집계해 회색으로 계속 표시합니다. 적재가 끝나면 운반 목록에서 빠집니다. 현재 적층 상태를 보여주는 수치이며, 이후 요청이나 재배치까지 포함한 최종 이동 횟수 예측은 아닙니다.

선택한 목표 빈의 현재 디깅·반출·포트 인계·회수·보관 복귀 담당 로봇을 강조합니다. 목표 빈을 직접 다루는 최종 로봇도 접근부터 인계 후 그리퍼가 복귀할 때까지 표시하며, 이후 빈손 이동과 과거 참여 로봇은 제외합니다. 여러 대가 협업하면 모두 표시합니다. 최적화 로봇은 실제로 선택 빈을 운반할 때만 최적화 작업명으로 표시합니다. 큰 3자리 번호와 접근·그리퍼 하강·체결·인양·운반·적재·복귀 단계를 함께 보여줍니다. **디깅 함께 보기**는 목표·상부 빈·담당 로봇의 현재 위치를 한 번에 화면에 맞추며, 이후 카메라를 강제로 움직이지 않습니다.

10만 SKU는 등록 가능한 품목 수의 상한입니다. 실제 배정 수는 설계 수용량을 따르며 초과 품목은 미배정으로 남습니다. 재고 표는 50개 단위로 상세 위치를 계산하고 검색 결과를 재사용합니다. 10만 SKU 구성 ID가 든 설계를 다시 불러올 수 있도록 설계 JSON 가져오기는 5MB까지 지원합니다.

### 패닝 방향

휠 버튼(가운데 버튼)을 누르거나 Shift를 누른 채 드래그하면 그리드가 마우스를 움직인 방향으로 이동합니다. 위아래 패닝의 부호를 보정했으며, 좌우 패닝과 왼쪽 드래그 회전은 기존 조작을 유지합니다. 일반 시뮬레이션과 빈 추적 화면, 편집 평면 보기에서 같은 방향으로 조작할 수 있습니다.

`dist/release-info.js`의 릴리스 목록을 최신 버전부터 관리합니다. 배포 시 기능 추가는 가운데 번호, 수정은 마지막 번호, 호환되지 않는 큰 변경은 첫 번호를 올리고 변경 내역과 날짜를 함께 기록합니다. 첫 명시적 버전은 **1.0.0 · 2026-11-14**입니다. 화면과 변경 기록은 동일한 데이터에서 생성하며 과거 버전을 소급해 만들지 않습니다.

## 저장과 초기화

설계와 사용자 정의는 브라우저 `localStorage`에 저장합니다. 새 키는 **`wedraw-wms-layout-v1`**입니다. 새 키가 없으면 기존 **`evio-gridlab-layout-v1`** 데이터를 읽고, 이후 저장은 새 키를 사용해 기존 설계·주문 정의를 이어받습니다.

| 유지하는 데이터 | 다시 구성하는 실행 상태 |
| --- | --- |
| 그리드·높이·빈 규격·구획·포트·로봇·SKU 구성 ID·다음 발급 번호·시드 | 시뮬레이션 시간, 현재 로봇 위치·작업·경로 |
| 고객 주문 정의 | 요청 큐, 피킹 진행·출고 결과, 포트 내부의 실행 상태 |
| 유휴시간 자동 최적화 설정 | 현재 더미 재고 수량, 빈의 실행 중 배치, 완료 알림 |

새로고침은 저장된 정의를 불러와 주문을 대기 상태로 구성하고 더미 재고와 실행을 처음부터 시작합니다. 진행 중인 시뮬레이션의 체크포인트를 저장하는 기능은 포함하지 않습니다. 같은 브라우저·같은 사이트의 로컬 저장이며, 서버 동기화나 다른 기기와의 공유는 하지 않습니다. 브라우저 저장이 차단되면 화면에 저장 불가 상태를 알립니다.

편집 초안의 변경 적용을 확정하면 재고와 실행을 초기화하고 저장된 주문 정의를 유지합니다. 편집 취소는 원래 운영 상태를 보존합니다. SKU 추가·삭제는 남은 재고와 빈 위치를 보존하는 별도 처리이며, 삭제된 SKU 구성도 저장되어 새로고침 후 되살아나지 않습니다. 설계의 실행 취소는 초안 편집 이력을 되돌립니다.

설계 JSON 가져오기·내보내기는 그리드 설정을 대상으로 합니다. 재고 CSV와 주문 CSV는 현재 표시·실행 결과를 확인하는 용도입니다.

## 모델의 적용 범위

공개된 격자·빈·포트 사양과 빈의 실제 이동·소유권·수량 보존을 반영합니다. 구조 강도, 벨트 장력, 마찰·모터 토크, 안전 센서·PLC 제어, 실측 작업자 시간과 운송 설비는 계산하지 않습니다. 표시되는 시간·속도·처리량은 모델 입력과 정책의 결과이며 실제 설치의 성능 보증이나 투자 타당성 값으로 사용할 수 없습니다.

공개 사양, 앱의 선택값, 현장 CAD·로그로 보정할 항목을 확인하려면 [물리 모델과 공개 사양의 적용 범위](docs/physical-model.md)를 참조하세요. 원문 자료 링크도 해당 문서에 함께 기록되어 있습니다.


v1.1.0 화면 확인: [목표 빈의 최종 담당 로봇](docs/screenshots/target-carrier-v110.jpg), [행 형태의 운영 작업 목록](docs/screenshots/operation-list-v110.jpg), [낮은 3빈 포트와 두 인계 타워](docs/screenshots/compact-port-v110.jpg). 30대 직접 입력과 실제 배치 대수 안내, 변경 없는 버튼·Esc 종료, 변경 후 취소 선택, 종료 후 진행 중인 20개 작업과 일시정지 상태 보존도 확인했습니다.

`tests/robot-continuation.test.mjs`는 디깅 후 현재 위치에서의 배정, 완전한 그리퍼 복귀, 좁은 배치의 접근성, 단독 담당 로봇 유지와 30대 실제 배치·출고를 검사합니다. `tests/port-footprint.test.mjs`는 네 방향·세 빈 높이에서 렌더된 외장·덮개·타워의 미예약 셀 침범, 한 회전 전체의 실물 빈 간격, 두 샤프트로 제한된 높은 외장을 검사합니다.

### 폴더블·모바일 조작 (v1.3.1)

실제 CSS 화면 폭을 기준으로 접힌 화면, 펼친 화면과 가로 방향에 대응합니다. 시뮬레이션에서는 한 손가락으로 회전하고 두 손가락으로 이동·확대합니다. 편집에서는 한 손가락으로 선택한 도구를 사용하며 두 번째 손가락이 닿으면 미완료 배치를 취소하고 화면 이동으로 전환합니다. 바닥 설정 패널을 닫거나 바닥 적용을 누르면 셀 배치 도구가 나타납니다. 화면 전환은 저장된 설계나 카메라의 회전·확대 설정을 초기화하지 않습니다.

주요 터치 버튼은 44px 이상, 입력창은 16px 글씨로 조정했습니다. 좁은 화면의 주문 목록은 세로 행으로 표시하고 재고 표는 내부 가로 스크롤을 유지합니다. 브라우저 주소창·안전 영역과 화면 키보드에 대응하는 동적 높이를 사용합니다. 자동 검증은 실제 장면 포인터 처리기의 다중 터치, 취소, 잔여 손가락 오배치 방지를 포함합니다. 기기별 네이티브 동작은 실기기 확인이 추가로 필요합니다.
